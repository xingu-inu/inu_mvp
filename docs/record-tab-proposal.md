# 기록 탭 개편안

> Roadmap(설계) + 기록(기록) — 2페이지 구조 개편

## 배경

### 왜 바꾸는가

기존 구조는 **Roadmap + Timeline**이었다.
체크인(일일 done/skip/miss 트래킹)이 제거되면서 Timeline의 역할이 모호해졌다.

- Timeline은 "기록하는 곳"이었지만, 체크인 없이는 기록할 행동 데이터가 없다
- inu는 캘린더/일정관리 앱이 아니다. 큰 틀에서 목표를 설정하고 기간 동안 진행/달성 여부를 다루는 앱이다
- 본질적으로 **"나를 담는"** 느낌을 주고 싶다

### 핵심 전환

```
기존: "무엇을 했나" (행동 기록)
개편: "나는 누구인가" + "나의 흐름" (정체성 + 여정)
```

## 구조

### Roadmap — 설계하는 곳 (변경 없음)

내 인생의 방향을 설계하는 캔버스. 기존과 동일.

### 기록 — 기록하는 곳 (개편)

**두 영역**으로 구성된다.

#### 나에 대한 데이터 (자유 프로필)

나에 대한 정보를 자유롭게 기록하는 공간.

- 사용자가 **라벨과 값을 직접 정의**한다. 시스템이 카테고리를 강제하지 않는다
- 넣고 싶은 만큼만 넣는다. 빈 화면도 괜찮다
- 항목마다 **설정한 날짜(타임스탬프)**가 남는다 — 언제 이걸 중요하게 여기기 시작했는지

| 예시 항목        | 예시 값                          |
| ---------------- | -------------------------------- |
| MBTI             | INTJ                             |
| 사주             | (자유 텍스트)                    |
| 강점             | 몰입력, 분석력                   |
| 요즘 관심사      | 클라이밍, 글쓰기                 |
| 에너지 충전법    | 혼자 산책                        |
| 올해의 테마      | 깊이 있는 삶                     |
| 피하고 싶은 패턴 | 비교하다 계획만 과하게 세우는 것 |

AI가 대화 맥락에서 **"이런 것도 추가해보시겠어요?"** 같이 가볍게 제안할 수 있다.

#### 나의 흐름 (타임라인)

데일리 일직선 타임라인. 나의 변화와 흐름을 시간순으로 본다.

| 이벤트 유형        | 설명                                          |
| ------------------ | --------------------------------------------- |
| 목표 상태 변경     | Active → Paused, Completed 등 + 이유          |
| 방향 변경          | Direction 수정/전환 기록                      |
| 프로필 항목 변경   | 자유 프로필 항목 추가/수정/삭제 이력          |
| AI 대화 하이라이트 | 주요 대화 요약 (방향 관련 대화, 고민 정리 등) |

**영역별 필터**: 타임라인 상단에 영역 칩 필터 (`전체` / `건강` / `커리어` / `관계` / ...)로 해당 영역의 흐름만 모아볼 수 있다.

## 레이아웃

### Desktop — 좌 → 우

```
┌──────────────────┬──────────────────────────────┐
│  나에 대한 데이터   │  나의 흐름                     │
│  (280-320px 고정)  │  (나머지 영역)                  │
│                    │                               │
│  MBTI: INTJ       │  [전체] [건강] [커리어] [관계]  │
│  강점: 몰입력      │                               │
│  사주: ...         │  ──●── 3/31 방향 전환          │
│  관심사: 클라이밍   │  ──●── 3/25 새 목표 추가       │
│                    │  ──●── 3/20 관심사 업데이트     │
│  + 항목 추가       │  ──●── 3/15 목표 Archive       │
│                    │  │                             │
│  (자체 스크롤)      │  ▼ (스크롤)                    │
└──────────────────┴──────────────────────────────┘
```

### Mobile — 위 → 아래

```
┌─────────────────────┐
│  나에 대한 데이터      │
│  MBTI · 강점 · ...    │  ← 접힘/펼침 가능
│  + 항목 추가          │
├─────────────────────┤
│  [전체][건강][커리어]  │
│  ──●── 3/31 방향 전환 │
│  ──●── 3/25 새 목표   │
│  ▼ 스크롤             │
└─────────────────────┘
```

- 왼쪽(위) = 정적 — 자주 안 바뀌는 프로필
- 오른쪽(아래) = 동적 — 계속 흐르는 타임라인
- 모바일 상단 프로필은 접힘/펼침으로 타임라인 공간 확보

## 데이터 모델 변경

### 기존: Companion Memory (고정 6필드)

profiles 테이블에 고정 컬럼:

```
life_compass, current_season, core_values,
support_preferences, reflection_focus, anti_patterns
```

문제: "삶의 나침반을 한 줄로 적으세요" — 무겁고 대부분 빈칸으로 남는다.

### 개편: profile_traits (자유 key-value)

```sql
profile_traits
├── id           UUID PK
├── user_id      UUID FK → profiles
├── label        text       -- 사용자가 정한 이름 (예: "MBTI", "강점")
├── value        text       -- 내용
├── sort_order   text       -- fractional-indexing 정렬
├── created_at   timestamptz
└── updated_at   timestamptz
```

- 사용자가 항목 수를 자유롭게 결정
- label도 value도 사용자가 직접 정의
- 항목 추가/수정 시 created_at/updated_at로 타임라인에 자동 기록
- 기존 companion memory 6개 필드 → 완전 대체

## AI 연동

### 프로필 데이터 → AI 시스템 프롬프트

기존 `buildCompanionMemoryBlock`이 고정 6필드를 주입했던 것처럼,
profile_traits의 모든 항목을 AI 시스템 프롬프트에 주입한다.

```
[사용자 프로필]
- MBTI: INTJ
- 강점: 몰입력, 분석력
- 요즘 관심사: 클라이밍, 글쓰기
- 피하고 싶은 패턴: 비교하다 계획만 과하게 세우는 것
```

AI는 이 데이터를 대화 맥락으로 활용한다.

### AI → 프로필 항목 제안

대화 중 AI가 사용자에 대해 새로운 것을 알게 되면:

- "사주 정보도 넣어보시겠어요?"
- "방금 이야기한 '혼자 시간이 필요한 타입'이라는 것도 기록해둘까요?"

사용자 동의 후 프로필에 추가.

## 두 영역의 관계

- 프로필 항목이 바뀌면 → 타임라인에 자동 기록 (추가/수정 이벤트)
- 타임라인에서 과거 시점을 보면 → 그때의 프로필 상태와 연결
- 시간이 쌓일수록 **"나라는 사람의 변화사"**가 만들어진다
