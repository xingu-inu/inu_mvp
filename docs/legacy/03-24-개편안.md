## 2. 3대 핵심 기능

### 2-1. Why 맵 (로드맵 = Why 맵)

기존 로드맵 트리 뷰를 **Why 중심 시각화**로 진화시킨다.

- 각 노드(방향, 영역, 목표)에 **"왜"가 서브타이틀로 상시 표시**
- 목표 간 공유 태스크가 있으면 **연결선**으로 시각화
- 연결선 두께 = 공유 태스크 수 비례 (접점이 많을수록 굵은 선)
- 선택된 목표의 연결만 하이라이트 (과밀 방지)

```
방향: "건강하고 당당한 삶"
  ├── 건강 (왜: "오래 살고 싶으니까")
  │     └── 헬스하기 (왜: "체력이 모든 것의 기반")
  │           ├── 상체 운동 ─────────┐ 공유 태스크
  │           └── 하체 운동 ─────────┤
  │                                   │
  └── 외모 (왜: "자신감을 올리고 싶어") │
        └── 운동하기 (왜: "탄탄한 몸") │
              ├── 상체 운동 ─────────┘
              └── 하체 운동 ─────────┘
```

### 2-2. 공유 태스크

하나의 태스크가 **여러 목표에 동시 기여**한다.

- 예: "상체 운동" → 건강/헬스하기 + 외모/운동하기 둘 다 진행
- 체크인은 태스크 단위 1회. 연결된 모든 목표의 진행률에 반영
- Why 맵에서 연결선으로 시각화
- 태스크 클릭 시 "이 태스크가 기여하는 목표들" 표시

**데이터 모델:**

`task_goal_links` 테이블 (junction table)로 구현. 기존 `related_goal_ids` 배열 대체.

```
task_goal_links
  - task_id (FK → tasks)
  - goal_id (FK → goals)
  - group_id (FK → groups, nullable)
```

### 2-3. 목표 시작 버튼

목표를 만들어도 **바로 시작이 아니다**. 준비되면 "시작하기"를 누른다.

**생명주기:**

```
[구상 중] draft ──(시작하기)──→ [진행 중] active ──→ completed / paused / archived
```

- 목표 생성 시 기본 상태: `draft` (구상 중)
- "시작하기" 누르면: `start_date` 설정, `status` → `active`
- Draft 목표의 태스크는 Home에 안 보임 → 시작 후 자동 노출
- 트리에서 draft 목표는 점선 테두리로 구분

## 5. 핵심 사용자 시나리오

### 시나리오: "운동으로 건강과 외모를 동시에"

1. 온보딩에서 "건강", "외모" 영역 설정
2. 건강 → "헬스하기" 목표 생성 (draft)
3. 외모 → "운동으로 몸 만들기" 목표 생성 (draft)
4. "상체 운동", "하체 운동" 태스크를 두 목표에 연결
5. Why 맵에서 두 목표 사이 연결선 확인 → "이거 한 번이면 두 목표 다 진행되네"
6. 준비 완료 → 두 목표 모두 "시작하기" 클릭
7. 매일 체크인 → 한 번 체크인으로 두 목표 진행률 동시 증가
8. Why 맵에서 "왜 이걸 하는지" 항상 보임 → 동기 유지
